# Deployment readiness (Phase 13, 2026-10-29)

**Verdict: safe to run locally and in containers for a demo; not ready for public deployment.** No deployment was
performed, no account was created, nothing was pushed. Reasons it is not public-ready are in section 6.

## 1. Dependency risks and what was done

| Area | Before | After | Evidence |
|---|---|---|---|
| Next.js | 14.2.18: `npm audit` reported 4 advisories incl. 1 critical (dozens of Next CVEs, last fixed in 15.5.28+ / 16.x) | **16.4.3**, React 19.2.0, React Three Fiber 9.8.2, Drei 10.7.9, lucide-react 1.64.0 | `npm audit`: **0 vulnerabilities** (prod and dev) |
| Frontend test tooling | vitest 2.1.9 (critical advisory chain via tinypool/vite) | vitest 5.0.5 + vite 7 + @types/node 24 | `npm audit` 0; 34 tests pass |
| Lint | `next lint` (removed in Next 16) | ESLint 9 flat config (`eslint.config.mjs`, `eslint-config-next` 16.4.3); `npm run lint` = `eslint .` | clean |
| Backend web stack | FastAPI 0.115.6 / Starlette 0.41.3: 14 Starlette advisories | FastAPI 0.162.0 / Starlette 1.10.0, pytest 9.0.3 | `pip-audit -r requirements.txt`: no known vulnerabilities; `pip check` clean |
| PyTorch | 2.5.1: 6+ advisories (fixed up to 2.13.0) | 2.13.0 CPU | 98 backend tests pass; checkpoints load with `weights_only=True` |

Migration changes needed: React 19 ref types (`RefObject<T | null>`); React-compiler lint rules required moving
setState-in-effect patterns (camera result tagging by `runId`, async webcam detection), refs-in-render (Humanoid), and
a setter instead of mutating `player.rate`. `tsconfig.json` was updated by Next (`jsx: react-jsx`). Lockfile
regenerated by npm. A pre-upgrade backup of `package.json` and the lockfile was kept in the session scratch folder.
Not audited: PyTorch CPU wheels from the PyTorch index (no PyPI listing for the `+cpu` build; the same version was
audited via PyPI), and the `@mediapipe/holistic` npm package's bundled WASM.

## 2. Security audit

| Check | Result |
|---|---|
| Hardcoded secrets | None found (pattern search of source, config, Docker and scripts). No secret is used by the project |
| `.env` exposure | No `.env` files exist; `.gitignore` covers `.env`, `.env.local`, models, datasets and video; `.dockerignore` excludes env files, venv, node_modules, models, data, docs |
| CORS | Explicit origin list (`SIGNBRIDGE_CORS_ORIGINS`), GET and POST only, no credentials; foreign origins get no CORS header (tested) |
| Input validation | Pydantic limits: 300 frames, text 500 chars, gloss list 50; malformed input is 422 (tested). **New:** requests with `Content-Length` above `SIGNBRIDGE_MAX_BODY_BYTES` (2 MB) get 413 (tested). Chunked bodies without a length are not capped here, so put a proxy limit in front for public use |
| Error responses | FastAPI validation and our `detail` strings; a test checks that no traceback or source path appears. **Fixed:** `/api/model/status` leaked an absolute local path; it now returns `models/isl_model.pt`, and load-failure details stay in the server log |
| Logging | Startup model state and load warnings only. No request bodies, landmarks or user text are logged by the app; uvicorn access logs record method, path and status |
| Webcam privacy | No `MediaRecorder`, canvas export, storage or upload of frames anywhere in `frontend/src`; only landmark arrays are posted, and only when you press a button; camera stops release tracks; the landmark buffer is cleared on stop |
| File uploads | None exist |
| Security headers (frontend) | `nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`, `Permissions-Policy: camera=(self), microphone=(), geolocation=()` (verified with curl). **No Content-Security-Policy**: MediaPipe WASM and Next scripts need `wasm-unsafe-eval` and nonces; add and test one before public use |
| Datasets and assets | None bundled. Licensing and conflicts documented in `DATASET_GUIDE.md`; the clip format requires author and license; sign records track license and attribution |
| Containers | Run as non-root users; no secrets baked in; models and clips mounted read-only |
| Secret rotation | Nothing to rotate. If a secret is ever added or leaked: revoke it at the issuer, issue a new one, update the environment variable, purge it from Git history if it was committed, and redeploy |

## 3. Local setup reliability (executed)

- `.\scripts\setup.ps1`: **executed to completion** (exit 0, 8 s) on the existing environment: venv present, dependencies
  satisfied, `npm install` up to date. It has not been run on a fresh machine or empty folder.
- Startup: backend `uvicorn app.main:app --port 8010` and frontend `npm run dev -- -p 3011` started; `/api/health` and the
  UI loaded; status panel showed "Backend connected" (browser). `scripts\dev.ps1` was **not** executed (it opens
  separate windows); the commands it wraps are the ones verified above.
- Environment variables: `SIGNBRIDGE_CORS_ORIGINS`, `SIGNBRIDGE_MODEL_DIR`, `SIGNBRIDGE_ANIMATION_DIR`,
  `SIGNBRIDGE_TRANSLATION_CONFIG`, `SIGNBRIDGE_SIGN_REGISTRY`, `SIGNBRIDGE_MIN_CONFIDENCE`, `SIGNBRIDGE_MAX_BODY_BYTES`,
  `NEXT_PUBLIC_API_URL` (see `.env.example`).
- Missing model: reported as `not_trained`; corrupt model: `error` with the detail in the log; missing vocabulary or
  registry: 503. All tested.

## 4. Containers (built and run)

Files: `backend/Dockerfile`, `frontend/Dockerfile`, `docker-compose.yml`, `.dockerignore`.

- `docker build -f backend/Dockerfile -t signbridge-api:phase13 .`: succeeded, **1.48 GB** (mostly CPU PyTorch).
- `docker build -f frontend/Dockerfile --build-arg NEXT_PUBLIC_API_URL=... -t signbridge-web:phase13 .`: succeeded, 460 MB
  (Next standalone output).
- Run test: API on host port 18000 and web on 13000 (the default ports were busy with other programs): `/api/health` ok,
  model status `not_trained`, registry served, security headers present, non-root user, and the browser showed
  "Backend connected" from the containerized UI to the containerized API across origins.
- `docker compose up` itself was **not** run (default ports 8000/3000 are in use here); the compose file was not
  exercised end to end. `NEXT_PUBLIC_API_URL` is baked into the web image at build time.
- Provisioning: mount trained weights (`isl_model.pt`, `labels.json`) at `/srv/backend/models` and clips at `/srv/animations`;
  never bake private data into an image.

## 5. Hosting assessment (no deployment performed; provider pricing and limits were not researched)

| Requirement | Implication |
|---|---|
| Python 3.11 runtime | Container host or VM; the API image needs about 1.5 GB of disk and an unknown amount of RAM with a loaded model (not measured, no model) |
| MediaPipe | Runs **in the browser**; the server does not need it in production (only for offline dataset preprocessing) |
| GPU | Not needed for a small BiGRU on 32 x 225 inputs (CPU inference time unmeasured until a real model exists) |
| HTTPS | Required for `getUserMedia` on non-localhost origins; terminate TLS at the host or a proxy |
| Frontend | The page is fully client-side, so it could also be exported as static files; the current build uses the Next standalone server |
| Frontend to API | Set `NEXT_PUBLIC_API_URL` at build time and `SIGNBRIDGE_CORS_ORIGINS` to the exact web origin |
| Timeouts and latency | Requests are small (under 0.2 MB) and fast locally (Phase 9: median 57 ms for a 60-frame extract call on localhost); WAN latency unmeasured |
| Asset hosting | Clips are small JSON files served by the web app; models are mounted volumes |
| Cost / free tiers | Not researched. Check each provider's current limits for image size, RAM and sleeping policies before choosing |

Suggested path when approved: one small VM or container service running both images behind a TLS proxy with a body-size
limit, after the items in section 6.

## 6. Why it is not ready for public deployment

1. No trained model and no sign clips: the public site would demonstrate only infrastructure.
2. No Content-Security-Policy, no rate limiting, no authentication, and no request-size cap on chunked bodies.
3. No TLS or proxy configuration has been written or tested.
4. Webcam behaviour has not been verified on a physical camera.
5. The `+cpu` PyTorch wheel and the MediaPipe WASM package were not covered by an advisory scan.
6. No deployment smoke test, monitoring or backup plan.
